# Console translations

The console uses **ngx-translate**: translations are loaded at runtime from `/assets/i18n/<lang>.json` (`provideTranslateHttpLoader` in `src/app/app.config.ts`), so switching language needs no rebuild. Languages: English (`en`) and French (`fr`).

## Using a key

```html
<h1>{{ 'dashboard.finance.title' | translate }}</h1>
<p>{{ 'dashboard.projectCard.updated' | translate: { date: updatedAt() } }}</p>
```

```ts
private readonly translate = inject(TranslateService);
const label = this.translate.instant('common.save');
```

Keys are nested by area: `common.*`, `validation.*`, `navigation.*`, `errors.*`, `chat.*`, `projects.*`, `dashboard.<component-or-page>.*`, and so on. Every key must exist in **both** languages.

## Files

```
public/assets/i18n/
├── en.json, fr.json          what the app loads — generated by merge
└── split/                    what you edit
    ├── index.en.json, index.fr.json
    ├── shared/<area>/en.json, fr.json        common, validation, navigation, errors, modes, tour, components
    └── modules/<module>/…/en.json, fr.json   chat, projects, onboarding, guided, dashboard/components, dashboard/pages
```

Each split folder mirrors a part of `src/app` and owns one branch of the key tree. The mapping from folder to key prefix (for example `modules/dashboard/pages/finance` → `dashboard.finance`) is the `pathToKeyMapping` table in `scripts/smart-merge-i18n.js`, shared with the split script.

## Workflow

| Script | What it does |
|---|---|
| `npm run i18n:merge` | Builds `en.json` / `fr.json` from the split files (`smart-merge-i18n.js`) |
| `npm run i18n:split` | Pushes keys from `en.json` / `fr.json` back into the split files, keeping existing translations (`smart-split-i18n.js`) |
| `npm run i18n:sync` | Merge, then split: the two representations agree afterwards |
| `npm run i18n:normalize` | Checks that `en` and `fr` have the same structure and moves misplaced `dashboard.*` keys (`normalize-i18n.js`) |
| `npm run i18n:split:legacy`, `i18n:merge:legacy` | Older, non-incremental versions of split and merge; do not use for new work |

Adding text:

1. Add the key to the `en.json` **and** `fr.json` of the split folder that owns the component (add a `pathToKeyMapping` entry for a new folder).
2. `npm run i18n:merge`.
3. Reload the app and check both languages.

If you edited `en.json` / `fr.json` directly, run `npm run i18n:split` so the split files do not overwrite your change at the next merge. Commit the split files and the merged files together.

A missing key shows the raw key in the interface: search the running app for strings like `dashboard.` before a release.
