# Landing translations

The landing site uses **`@angular/localize`** (compile-time i18n): each locale is a separate build. English is the source locale; French is the only translation (`angular.json › i18n.locales.fr`).

## Marking text

Every visible string carries an explicit, stable id:

```html
<h1 i18n="@@home.hero.title">Welcome to IDEM</h1>
<img i18n-alt="@@home.hero.imageAlt" alt="IDEM dashboard" src="…" />
```

```ts
const label = $localize`:@@pricing.cta.start:Start for free`;
```

Use `<page-or-component>.<section>.<key>` for ids. Never rely on generated ids: they change when the text changes and break the translation.

## Files

```
src/locale/
├── messages.json        English, generated by extraction — do not edit by hand
├── messages.fr.json     French, generated by merge — the file the build reads
├── en/                  English, split by owner
│   ├── common.json
│   ├── meta.json
│   ├── components/<component>.json
│   ├── pages/<page>.json
│   └── shared/components/<component>.json
└── fr/                  French, same structure — edit translations here
```

All files use Angular's JSON format:

```json
{ "locale": "fr", "translations": { "home.hero.title": "Bienvenue sur IDEM" } }
```

Placeholders such as `{$INTERPOLATION}`, `{$START_TAG_SPAN}` or `{$LINE_BREAK}` must be kept exactly as they are in the translation.

## Workflow

| Script | What it does |
|---|---|
| `npm run i18n:extract:json` | `ng extract-i18n --format=json` into `src/locale/messages.json` |
| `npm run i18n:organize` | Splits `messages.json` into `src/locale/en/{components,pages,shared}` by id prefix (`scripts/organize-i18n-by-components.js`) |
| `npm run i18n:workflow` | Extract, then organize |
| `npm run i18n:merge` | Merges `en/` and `fr/` back into `messages.json` and `messages.fr.json` (`scripts/merge-i18n-components.js`) |
| `npm run build:all-locales` | Merge, then build `en` and `fr` |

Adding or changing text:

1. Add the `i18n` attribute or `$localize` call with a new id.
2. `npm run i18n:workflow` to refresh the English files.
3. Add the French string under the same id in the matching `src/locale/fr/…` file.
4. `npm run i18n:merge`, then check with `npm run start:fr`.

A missing French translation falls back to the English text and prints a build warning: treat those warnings as bugs.
