# Languages: already set up, always used

The starter contains a language system (`src/i18n/`, under `frontend/` for a web app). The app has one language today; the user may ask for another tomorrow. Writing every visible text through `t()` now is what makes that a translation file instead of a rewrite.

## Already written — do not emit these files

```
src/i18n/index.js                t, useLanguage, setLanguage, formatNumber, formatDate, formatCurrency, LanguageRoot
src/components/LanguageSwitcher.jsx   the language buttons (renders nothing while there is one language)
src/main.jsx                     <LanguageRoot><App /></LanguageRoot> — switching language re-renders the app
```

## How to write texts

- Every text a user sees or hears goes through `t()`, written in the app's language (the one in `src/i18n/config.json`): titles, buttons, labels, placeholders, `alt`, `aria-label`, empty states, toasts, error messages.
  ```jsx
  import { t } from '@/i18n';
  <h1>{t('Mes commandes')}</h1>
  <input placeholder={t('Rechercher un produit')} />
  <p>{t('Bonjour {name}, vous avez {count} commandes.', { name: user.name, count: orders.length })}</p>
  ```
- One whole sentence per `t()`, with `{placeholders}` for values: never split a sentence around a variable.
- Not through `t()`: data from the database or the API, user input, brand and product names, URLs, ids, class names.
- Numbers, dates and prices: `formatNumber`, `formatDate`, `formatCurrency(amount, 'XAF')` — never hand-format them.
- Put `<LanguageSwitcher />` in the settings screen or the top bar: it stays invisible until a second language exists.

## When the user asks for another language

1. Add its ISO code to `languages` in `src/i18n/config.json` (the first stays the default).
2. Write `src/i18n/messages/<code>.json`: every `t()` text of the app as a key, its translation as the value — natural, idiomatic, same length class (a button stays short), placeholders `{name}` unchanged.
3. Register it in `src/i18n/messages.js`: `import en from './messages/en.json'; export const messages = { en };`
4. Do not change the components: they already call `t()`.
